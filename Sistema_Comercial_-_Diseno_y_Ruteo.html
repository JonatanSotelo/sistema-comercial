1) Alcance

Este documento define el diseño funcional inicial del ERP liviano orientado a PyMEs con módulos de Proveedores, Compras/Pedidos, Stock/Inventario, Ventas, Logística/Entregas, Pagos, Adjuntos y Supervisión; y agrega una App de Ruteo con tracking en tiempo real.

Objetivo: cerrar el circuito pedido → compra → recepción → stock → venta → entrega → cierre con auditoría y KPIs básicos, dejando preparada la integración con facturación fiscal y contabilidad para fases posteriores.

2) Mapa de módulos & estados

Compras

Borrador → Pedido (Pendiente) → Aprobado → Recepción Parcial/Total → Cerrado

Ventas

Presupuesto → Pedido → Factura/Remito → Preparación → En tránsito → Entregado → Cerrado

Logística (Entregas)

Pendiente → Asignado → En tránsito → Entregado (Fallido si no se pudo).

Stock (Kardex)

Cada compra/recepción/venta/ajuste genera un movimiento IN/OUT auditable.

4) Flujos por módulo (paso a paso)

Compras

  1. Crear Pedido de compra (proveedor, ítems con cantidad y costo → status=Borrador).
  2. Confirmar → Pendiente. Adjuntar factura o presupuesto si aplica.
  3. Aprobar → Aprobado.
  4. Recepción parcial/total → crea IN en kardex y actualiza costo_ultimo.
  5. Cerrar compra.

Inventario

  • Consulta por producto muestra ubicación (depósito/etiqueta) y campos custom (JSONB).
  • Ajustes manuales (motivo) generan movimientos IN/OUT.

Ventas

  1. Cargar cliente o usar Mostrador. Elegir productos por nombre, sku o barcode.
  2. Elegir Factura o Remito; definir retiro o envío y quién paga el costo.
  3. Confirmar → Factura/Remito y generar OUT (reserva o salida según política).
  4. Si requiere envío, crear Entrega (logística) y remito de entrega.
  5. Cerrar venta cuando esté entregada y cobrada.

Logística

  1. Ver cola de entregas: asignar responsable (nombre/teléfono) y dirección de entrega.
  2. Al regresar, adjuntar remito firmado y marcar Entregado (o Fallido con motivo).

5) Documentos internos & adjuntos

  • Numeradores para: Pedido de compra, Factura/Remito, Entrega.
  • Generación de PDF para Facturas/Remitos internos (impresión rápida).
  • Adjuntos en compras/ventas/logística (facturas, remitos firmados).

6) Pagos y saldos (CxC/CxP) — básico

  • Registrar pagos/cobros por medio (efectivo/cheque/transferencia/tarjeta).
  • Saldo por cliente/proveedor por documento; vista de próximos 7/30 días.
  • Notas de crédito/devoluciones (fase 2).

7) Seguridad, roles y auditoría

  • Roles sugeridos: compras, ventas, logística, contable, supervisión.
  • Auditoría en CRUD y movimientos de stock.
  • Reglas: permitir o no stock negativo; ventas sin stock (configurable).

8) Lectores/Impresión de códigos de barras

  • Entrada con auto-focus en el front: los lectores actúan como teclado.
  • Endpoint búsqueda: GET /productos?barcode=CODE o GET /productos/by-barcode/CODE.
  • Fase 2: impresión de etiquetas (generación de EAN/Code128).

9) Dashboard de Supervisión (KPIs)

  • Ventas hoy/mes, top productos, entregas pendientes, compras abiertas.
  • Quiebres de stock, CxC/CxP próximos 7 días.

10) App de Ruteo y Tracking en tiempo real

Objetivo

Optimizar hojas de ruta para múltiples entregas (vehículo único o flota) y ofrecer tracking en tiempo real para cliente y vendedor, marcando entrega desde el móvil del repartidor.

Arquitectura propuesta

  • Servicio de ruteo (microservicio): calcula ruta óptima con Google Maps Distance Matrix + Directions, o alternativa OSRM/GraphHopper (OpenStreetMap) si se prefiere menor costo.
  • App móvil / PWA Logística: inicio/fin de turno, lista de paradas (stops), navegación paso a paso (abre Google Maps nativo), botón “Entregado/No Entregado”, captura de firma/foto.
  • Tracking web: enlace por entrega (/tracking/<token>) que muestra posición y ETA en tiempo real.
  • Tiempo real: WebSockets/SSE para publicar la ubicación viva del repartidor (frecuencia configurable, p.ej. cada 10–30s).
  • Persistencia: posiciones en delivery_positions (con retención) y estado de cada delivery_stop.
  • Privacidad: consentimiento del repartidor y del cliente; tokens expiran cuando la entrega finaliza.

API (borrador)

POST   /routing/plan
  body: { origen, paradas:[{ delivery_id, direccion }], estrategia, ventanas_horarias? }
  resp: { route_id, stops:[{ delivery_id, orden, eta }] }

GET    /routing/routes/{'}}route_id{{'}
GET    /deliveries/{'}}id{{'}/tracking             → datos para tracking público
WS/SSE /deliveries/{'}}id{{'}/positions/stream     → posiciones en tiempo real
POST   /deliveries/{'}}id{{'}/events               → entregado / fallido + notas, adjuntos

Selección de mapas

  • Google Maps: calidad superior de ETA y rutas urbanas; costo por uso (Distance Matrix, Directions, Maps JS/SDK).
  • OSRM/GraphHopper + OSM: costo bajo/propio, requiere hosting/afinación.

UX del repartidor

  1. Ver ruta del día con lista de paradas en orden.
  2. Tocar una parada → “Navegar” (abre Google Maps) o “Detalle”.
  3. Al llegar: “Entregado” (opcional firma/foto) o “Fallido” (motivo).
  4. La app envía posición periódica y estados → el cliente ve el tracking.

11) Roadmap por Fases

Fase 1 — MVP++ (ahora)

  • Estados y numeradores en compras/ventas/entregas.
  • Kardex (inventory_moves), depósitos/ubicaciones y JSONB de campos custom.
  • Cliente genérico, adjuntos, pagos simples.
  • Entrega básica y remito PDF; búsqueda por barcode.
  • Dashboard básico.

Fase 2

  • AFIP e-Factura (A/B/C), CxC/CxP avanzado y conciliación bancaria.
  • Impresión/etiquetas de códigos de barras.
  • Ruteo: primer despliegue productivo (Google u OSRM) + tracking público.

Fase 3

  • RR.HH. (asistencias/licencias) y BI avanzado.
  • Optimización de flota (múltiples vehículos, ventanas horarias, capacidad).

12) Sugerencia de primer sprint (co-trabajo sin estimar tiempos)

  1. Agregar campos y tablas base (status, numero, inventory_moves, attachments, deliveries).
  2. Endpoints mínimos por módulo (compras: aprobar/recepcionar; ventas: facturar/remitir; entregas: asignar/cerrar).
  3. Front: forms simples con lector de barras (auto-focus) y vista de ubicaciones.
  4. PDF de factura/remito interno y adjuntos.
  5. Dashboard con 5 KPIs (ventas día/mes, top 5, pendientes de entrega, compras abiertas, quiebres).
  6. Esqueleto del microservicio de ruteo (contratos de API y mock).

Nota: evitamos estimaciones de tiempo; priorizamos entregables concretos por iteración.

14) Glosario

  • Kardex: registro de movimientos de stock (IN/OUT) auditable.
  • JSONB: tipo de campo en PostgreSQL para datos flexibles.
  • Remito: comprobante de traslado/entrega de mercadería.
  • Tracking: seguimiento en tiempo real de la entrega con ETA.
